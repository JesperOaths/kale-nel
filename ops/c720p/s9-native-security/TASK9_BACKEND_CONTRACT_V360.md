- Queue active file: `state/s9-priority-rescan-v304/queue.json`, still schema `s9_priority_rescan_feedback_v304`, `revision` nonnegative integer, `rows` at most 340 with deterministic 64-hex `id`. Each row includes `status` in `pending | processing | completed | rejected | blocked | dead_letter`, integer `attempts` 0–3, `deferrals`, `next_attempt_at` and `lease_until` as Unix UTC seconds, and original `source_sha256`, `source_bytes`, `media_revision`, `model_sha256`, `required_analysis`, `priority_reason`, `last_reason` and bounded `outcome`. No human identity or approval fields.
- New terminal ledger: private `state/s9-priority-rescan-v304/terminal-archive-v360.json`, schema `s9_priority_rescan_terminal_ledger_v360`, with `rows` map from deterministic `id` to full immutable terminal row for `blocked | rejected | dead_letter`. At most 10,000 entries and 16 MB; **if full, reject admission rather than delete audit history**. A compacting producer first fsyncs a whole ledger snapshot and then atomically replaces the active queue. On interrupted commit, only identical duplicate terminal rows may be reconciled. A blocked same-detector negative does not become runnable on a periodic producer tick. A newly verified original revision or separately validated model generates a new ID, preserving older provenance.
- `produce`, `work` and `status` return `tally` object with integer keys for all six states and `archived_terminal` (0–10,000). `tally.blocked` includes archived and active blocked; therefore `tracked` from the active queue alone is no longer the all-time total. Existing direct readers of the private queue must not claim active `rows.length` equals historically admitted count. `status` does not process footage.
- The 245 previously blocked `secondary_detector_has_no_supported_face` entries remain **permanently unsupported for a second run with the same YuNet model**. They are not automatically retried and do not establish absence or identity of a person.
- A processing lease is bounded to 240 seconds, three attempts and eight guarded dependency deferrals; expired leases recover on the next worker tick. Camera must be idle, healthy 4K with >=6500ms ring, zero dropped output frames, temperature <=34.5°C, hub >=850 MiB root and >=900 MiB available RAM. Existing worker locks apply unchanged. No lowered guard is permitted.

## Authenticated Evidence Quality GET response (reader owned by Task9, router owned by Playback)

`GET /new/api/evidence-quality` must return HTTP 200 only when the underlying private report is readable and source attestation passes. `original_gap_benchmark` contains:
- `analysis_version` string, `detector_model_sha256` 64-hex string, `recordings` array (max 300), `source_binding_status` exactly `source_qualified_active_queue_only`;
- `source_bound_records_visible` nonnegative integer, `source_bound_records_not_current` nonnegative integer, `identity_inference_performed:false` and `original_recordings_modified:false`.
- Each visible row binds the original `clip_no`, exact 64-hex `source_sha256`, integer `source_bytes`, 64-hex `source_revision`, exact `model_sha256`, `analysis_version`, and **three** `samples` at integer `time_ms`, each with `state:"decoded"`, `original_resolution:[3840,2160]` and `face_candidates` array. These are anonymous image observations, **not** human identities, similarity scores, or permissions to refile. A worker counts completion only after this exact object is present in the authenticated reader response.
- Admission and every read require current native catalog no indexed crop and current face pass, original SHA/bytes/version, qualified queue `processing` unexpired lease or verified `completed` outcome, and model provenance. `pending`, `blocked`, `rejected`, `dead_letter`, stale original/revision or superseded native pass/crop are not served. Revocation is evaluated at read time; cached consumer decisions must also expire/invalidate if underlying proof changes.
- Fail closed (503 / no eligible records), never silently fall back to unqualified historical rows. Private report `recordings` may retain stale derivative history, which does not authorize serving it.

Representative **sanitized** successful shape:
```json
{"ok":true,"original_gap_benchmark":{"analysis_version":"s9_original4k_independent_gap_benchmark_v1","detector_model_sha256":"<64-hex-digest>","source_binding_status":"source_qualified_active_queue_only","source_bound_records_visible":1,"source_bound_records_not_current":16,"identity_inference_performed":false,"original_recordings_modified":false,"recordings":[{"clip_no":"motion_<13-digit-ms>.mp4","source_sha256":"<64-hex-digest>","source_bytes":2300000,"source_revision":"<64-hex-version>","model_sha256":"<64-hex-digest>","analysis_version":"s9_original4k_independent_gap_benchmark_v1","samples":[{"time_ms":1000,"state":"decoded","original_resolution":[3840,2160],"face_candidates":[]},{"time_ms":3000,"state":"decoded","original_resolution":[3840,2160],"face_candidates":[]},{"time_ms":5000,"state":"decoded","original_resolution":[3840,2160],"face_candidates":[]}]}]}}
```

All time fields: event sample offsets in milliseconds from original start; queue scheduling Unix UTC seconds. Response freshness must be bound to the **current** catalog and queue, not a timestamp alone. Never promote a body containing only a matching filename to confirmed consumption.

## Appearance V3 compatibility and UI-owner handoff

Existing `GET /new/api/appearance-multivector-v3?clip=motion_<13digits>.mp4` returns `appearance_only:true`, `verified_same_person:false`, `human_review_required:true`, `automatic_person_assignments:0`, `similarity_percent` in 0–100, and a `coverage` section. Those are provisional clothing/appearance similarities, not face-to-person identity verification. Existing V3 source map pins crop SHA and model SHA and immutable V2 baseline, but does **not** carry current original MP4 SHA/bytes/version. Therefore a valid old V3 ranking cannot by itself prove a source is still current; UI must not claim `verified_source_current` or automatically file based on it. A future producer must issue a separate versioned original-bound V4 map and consumer before any such readiness claim. Pose/gait is unmeasured and must not be displayed as active capability.
